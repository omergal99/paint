A. User workflow coaching

Proposal

Start each round with Must fix, Should improve, Deferred, Evidence, and Release impact.

Concrete example

Must: Settings → App → Check for updates returns current; Evidence: Lighthouse JSON + 320px fixture; Deferred: Step 12.

Proof

The session repeatedly re-established the same evidence and reporting requirements. The new round template is persisted in memory/user_feedback.json.

Why

This keeps precise UX feedback while reducing context repetition and makes the handoff understandable before implementation starts.

B. Agent performance and automation

Proposal

Use small patches and run the narrowest check immediately, followed by the release gate.

Concrete example

npm run verify:docs, npm run audit:runtime, then npm run verify:release.

Proof

The new autosave teardown contract initially failed because cleanup assumed a browser-global window. The test exposed the issue; the implementation now uses injected targets and globalThis fallbacks.

Why

Automation converts repeated manual checks into a stable release boundary without pretending static metrics are runtime proof.

C. Domain and ecosystem audit

Proposal

Keep browser-specific PWA behavior explicit and protect active editing during service-worker activation.

Concrete example

Settings → App exposes native installation when available and manual guidance otherwise. A controller change now waits when a text editor or floating selection is active.

Proof

Fresh Chrome evidence shows the controller URL sw.js?version=1.6.0, “Paint is up to date,” reduced motion, and zero console errors. Installation prompts are not universal; see web.dev installation guidance.

Why

Service-worker updates are discovered through the registration lifecycle; version-keyed URLs still depend on disciplined version bumps. See MDN update() and MDN register().

D. Blind spots and future opportunities

  • Performance: Lighthouse Performance is 84, with 4.4s LCP. Do not call the 90+ target closed until bundling, code splitting, or CSS delivery is measured and improved.
  • Runtime: the listener census is not a leak detector. Add a real pointer trace and large-canvas memory journey before changing event ownership broadly.
  • Recovery: Blob/object-URL cleanup, quota errors, and IndexedDB recovery still need browser fixtures.
  • Release safety: immediate service-worker activation is useful, but future lazy assets can create mixed-version risk. Workbox documents this tradeoff in its lifecycle guidance.
  • Product scope: full editable text, Step 12 background removal, and Step 13 tabs/split/recovery remain deferred behind their proof gates.
